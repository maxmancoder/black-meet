# AGENTS.md

Persian (RTL) group voice/video-chat app like Google Meet. Single **Node.js** process: Express + Socket.IO + SQLite (`node:sqlite`), ported from an old PHP/Apache/MySQL app. Local dev on Windows. No tests, no linter, no build step except regenerating Tailwind CSS and the icon sprite.

## Local stack (all started by `start.bat` — double-click)

- Node app `server/index.js` :3000 — web pages (EJS), REST API, Socket.IO, static assets, SQLite. **Apache/MySQL/PHP are gone**; app is only reachable at port 3000, all routes under `/black-meet/*`. All app logs append to `logs/` (`logs\node.log`, `logs\turn.log`, `logs\turn-proxy.log`, `logs\dev_otp.log` — the folder is gitignored and `start.bat` mkdirs it).
- TURN `node turn.js` UDP :3478 (log `turn.log`), TCP relay `node turn-proxy.js` TCP :3478 (log `turn-proxy.log` — must be a SEPARATE file, both used to fight over `turn.log` and the proxy failed to bind).
- Website tunnel = `bin/tunnel.ps1` with fallback **Cloudflare (bin\cloudflared.exe) -> SSH localhost.run -> SSH serveo.net**. Writes the CURRENT public URL to `tunnel_url.txt` only AFTER a health check (`GET /black-meet/login` through the tunnel); copies it to the clipboard and opens it in Chrome once. Exactly ONE chain runs (global mutex + sibling-kill at startup — duplicate instances fight over `tunnel_url.txt`). **All methods point at `127.0.0.1:3000`** (never `localhost` — cloudflared resolves it to IPv6 `[::1]`). Log: `%TEMP%\bm-tunnel\bmt-chain.log`. On this network only Cloudflare resolves (localhost.run/serveo often fail) — the chain retries CF immediately on SSH failure; do NOT pass `--protocol http2` (causes `TLS handshake with edge error: EOF`).
- No bore/TURN tunnel anymore: `turn_host.txt` is read by `server/lib/helpers.js` `turnConfig()` as a legacy override but nothing writes it; cross-NAT media falls back to the metered.ca TURN in `turnConfig()`.
- `start.bat` must stay open and end with `pause` — don't remove the pause. It kills all BM processes when a key is pressed. Echo lines live inside `if` blocks: parentheses in the text break `cmd` block parsing (both branches run) — avoid them.
- `start.bat` falls back to `http://localhost:3000/black-meet/` when no tunnel URL is ready.

## Wiring / gotchas

- `base_url()`/`baseUrl(req)` (server/lib/helpers.js) **hardcodes the `/black-meet` path**. Routes: `/black-meet/login`, `/home`, `/create`, `/profile`, `/meeting?room=…`, `/messages`, `/members`, `/forgot-password`; API at `/black-meet/api/…` (e.g. `api/meetings/create`, `api/messages/conversations`, `api/themes`). The old `.php` alias/redirect layer was REMOVED — `.php` URLs now 404. The root `/socket.io/` path is served at the server root (not under `/black-meet`).
- The call-page member info panel fetches `GET api/members/:userId` (usable only for two users sharing an active meeting, or self).
- Always build URLs with `asset_url()/assetUrl()`/`asset()` — it appends `?v=<mtime>`. Hardcoded css/js paths are the classic "my change isn't showing" bug.
- Socket.IO event names are defined once in `shared/socket-events.js` (browser global `BMEv`, and `require`d by Node). Add/change events there, not as inline strings.
- Socket auth is an HMAC token (`makeSocketToken`/`verifySocketToken`), 24h TTL, `cfg.secret`. Watch the `|` delimiter format `userId|meetingId|ts.sig`.
- `server/lib/internal.js` is called directly by sockets (no HTTP hop). `broadcast_secret`/`BM_BROADCAST_SECRET` is unused but still read by `config.js`.
- Sessions are SQLite-backed (`bm_sessions`), cookie `bm`, httpOnly + SameSite=Lax + Secure-over-https. CSRF = 32-hex token in the session, verified on every POST (`csrfToken`/`csrfValid`). `establishLoginSession` rotates the sid on login.
- UI is Persian RTL; templates are EJS under `server/views/` (`head.ejs` partial). Keep UTF-8.
- `head.ejs` injects `window.BASE`, `window.__BM_LIVE_URL` (empty for logged-out pages — otherwise every page hammers `api/socket-token` with 401), the favicon link, `BM_SPRITE` + `assets/js/icons.js`, and `<link href="/black-meet/theme.css">` AFTER `tailwind.css`. **`assets/css/styles.css` is a BLOCKING stylesheet + two font preloads + sprite preload** — it was `media="print" onload` (async) once, which made `<svg class="bm-ico">` (no width/height) render at the SVG default 300×150 until CSS landed → giant layout jump on every page load. Don't reintroduce async CSS.
- **Ranks / daily quotas** (`server/lib/ranks.js`): `users.rank` ∈ `user|admin|premium` (+ `is_manager` = the seeded main manager `blackline`, always highest). Daily meeting-create limits: user=2, admin=5, premium=15, manager=unlimited, enforced server-side in `POST /api/meetings/create` (counted by local date `substr(created_at,1,10)`, resets at midnight, error msg contains `سقف تماس امروز`; response also carries `quota`/`quotaText`/`quotaFull` for the UI). `canViewMembers`/`canViewRequests`/`canDecideRequests`/`canManageUsers` gate `/members` (pages: `requireMembersAccess`) and the APIs; admin rank SEES requests but cannot approve/reject (403 `دسترسی ندارید`), premium sees both members+requests, manager has everything and his rank/row can't be changed by anyone else (`info_hidden` redaction hides his email/phone/username/hash from non-managers; client renders the note instead).
- **Signup modes** (`server/lib/settings.js`, key `signup_mode` in `bm_settings`): `open` (default, full signup + OTP) | `approval` (insert into `signup_requests`, reply `{ok:true, pending:true}` + the fixed PENDING_SIGNUP_MSG, NO account until approved, login blocked, applicant chats the manager via `/forgot-password?id=<phone>` → messages land in `signup_request_messages`) | `closed` (no insert, `SIGNUP_CLOSED_MSG` with 10s toast). Managed on `/members` (dropdown `#mode-btn`) via `POST /api/admin/signup-mode`; requests list/reply/decide via `GET|POST /api/admin/signup-requests` + `POST /api/admin/signup-requests/message`. The logged-out `view-signup-pending` in `index.ejs` is filled by `auth.js` from the API msg.
- **Fonts** (all local in `fonts/`, `@font-face` in `assets/css/styles.css` — paths are `../../fonts/…`, they live in a subdir, `../fonts` 404s): Persian text = **Entezar** (`fonts/Entezar.v1.00.ttf`, falls back to Tahoma/Arial for Latin — it has no Latin glyphs), headline/brand = **Digi Ghaf Bold** (`fonts/Digi Ghaf Bold.ttf`), **AFSANEH** (`fonts/AFSANEH.ttf`, Persian-only) is only wired to the optional `.font-brand` class which is intentionally NOT applied anywhere (the mockups in `دیزاین بلک میت/` use plain sans, not nastaʿlīq). Google Fonts/jsDelivr links are removed on purpose — do not re-add.
- **Icons: SVG sprite system**, not icon fonts. `icons/sprite.svg` (82 symbols `ic-*`) generated by `tools/gen-icons.js` from `fonts/material-symbols.woff2` (`npm i --no-save fontkit wawoff2` then `node tools/gen-icons.js`). Helpers: server `icon(name, cls, fill)` (in `server/routes/pages.js`, exposed via `pageLocals`), client `bmIcon()`/`setBMIcon()` in `assets/js/icons.js`. Always emit `<svg class="bm-ico"><use href="…/icons/sprite.svg#ic-name"></use></svg>`; filled variants use `fill` on the `<use>`.
- **NPM PRUNING GOTCHA**: every `npm install` removes `--no-save` packages. After any install re-run: `npm i --no-save fontkit wawoff2 puppeteer-core` (first two = sprite regen, puppeteer-core = screenshots against system Chrome `C:\Program Files\Google\Chrome\Application\chrome.exe`).
- **Tailwind is self-hosted, no CDN** (blocked in Iran). Config: `tailwind.config.js`; `npm run tailwind:build` → `assets/css/tailwind.css` (committed). Rebuild whenever you add new utility classes; JIT scans `server/views/**/*.ejs`, `assets/js/**/*.js`, `shared/**/*.js`.
- **Theming**: all brand colors are CSS vars `--bm-*` (RGB triplet format) defined in `:root` of `assets/css/styles.css` (the defaults) and overridden by files `دیزاین بلک میت/<id>.css`. Routes: `GET /black-meet/theme.css` (selected by cookie `bm_theme`, fallback = first file found, `Cache-Control: no-cache`) in `pages.js`, and `GET /black-meet/api/themes` in `api.js`. Tailwind colors are `rgb(var(--bm-*) / <alpha-value>)` — keep alpha syntax. Only theme shipped: `obsidian_flux`. Hex colors in `tailwind.config.js`/`styles.css` are a bug; convert them to vars.
- Custom control styles: `.ctrl-off` = red when a control is disabled, `.ctrl-live` = red while active (screen-share). Don't confuse them — share button had it backwards once.
- Screenshot smoke tests: `C:\Users\BlackLine\AppData\Local\Temp\opencode\shot.js` (login page; selectors `#le-email`/`#le-pass` + `switchView('view-login-email')`/`loginEmail()`), `shot2.js` (creates a meeting via `POST /api/meetings/create` with `csrf` in the BODY, joins `/meeting?room=…`). Note: a meeting's `room_id` ≠ title; when the last participant leaves `active=0` and the URL redirects to `/home?err=nomeeting` — always create a FRESH meeting for call tests. Also in temp: `e2e.js` (44 API checks: signup modes, approve flow, rank changes, daily quotas 2/15, redaction — cookie must be sent as `bm=<sid>`, store the FULL `bm=value` when absorbing Set-Cookie or CSRF fails with 403 `درخواست نامعتبر`), `e2e2.js` (31 checks: /messages access per rank, admin_chat thread both ways + `from_manager` direction, announcement gates manager+premium, 30-min decided-request visibility), `cleanup.js` (removes test users `testuser_bm|testregular|premium_bm|req30_bm` + their meetings/pv, test announcements `اعلان آزمایشی مدیر`/`اعلان پریمیوم`, test meetings `تست فوکوس`/`تست لایوت فوکوس`, signup_requests by test phones, resets `signup_mode=open`), `pngcheck.js` (pure-Node PNG decoder — pixel-verify screenshot content), `shot6.js` (17 labeled `s6-*.png` across members/rank-menu/edit-modal, mode dropdown, home bell+popup, messages manager/premium/admin-chat, mobile sidebar+chat switching, call focus desktop/mobile, avatar progress — asserts spinners stay off on `data-no-loader` keys, bell dot clears, header name = "Black Line"), `verify-dom.js` (9 DOM asserts: manager modal `مدیر اصلی` locked option, rank-menu card z-boost, sidebar links, focus layout cols `4fr/1fr` + mobile `1 / -1`), `probe-red.js`/`probe-pix.js` (paint-order probes: recolor an overlay red and decode pixels — the only trustworthy way to verify stacking, since Read shuffles images). **The Read tool sometimes returns SHUFFLED image attachments** (image bytes ≠ the file path requested): trust file hashes/sizes, `pngcheck.js` and pixel probes over what you "see".
- **Stacking gotcha**: `.bm-soft` (styles.css) has `will-change: transform`, so EVERY card/button with that class is its own stacking context — an absolutely-positioned menu with `z-index:40` inside card A still paints UNDER sibling card B (DOM order wins between sibling contexts). Hit-testing (elementFromPoint) can disagree with what you see; verify with `probe-red.js`. Fix pattern: while the menu is open boost its container (`toggleRankMenu` sets `card.style.zIndex='30'`, `closeMenus()` clears it). Same for `.rank-menu` (EJS inline CSS: `position:absolute; top:calc(100%+6px); z-index:40`). `messages.js` `setHeader()` must read `c.display_name || c.name` (the view object carries `name`, not `display_name` — passing the raw view rendered an EMPTY chat header name).

## Tooling / process pitfalls (this environment)

- Shell is PowerShell; `node -e` with regex/quotes is fragile — write scripts to `$env:TEMP\opencode\*.js` and run with `$env:NODE_PATH = "<repo>\node_modules"`.
- **NEVER let a shell command line contain `bin\tunnel.ps1` or `tunnel.ps1`**: its startup cleanup Stop-Kills every powershell whose command line matches that pattern, including the tool's own shell (commits suicide, takes the session with it). Create helper scripts with the file tools (`restart-chain.ps1`, `stop-all.ps1`, `debug-chain.ps1` in `$env:TEMP\opencode\`) and invoke them with `powershell -File`.
- Background processes started with `Start-Process` get killed by the harness; use WMI instead: `([wmiclass]'Win32_Process').Create('cmd /c "cd /d <root> && node server\index.js >> <log> 2>&1"')`. If the root path contains non-ASCII (this repo's Persian path), DON'T put it in a `.cmd` file (cmd reads batch in ANSI → garbled): make an ASCII `.ps1` that takes the root as a param (`start-server.ps1` in `$env:TEMP\opencode`, started via WMI `powershell -File … "<root>"`). To bounce the server after code changes use `restart-server.ps1 -Root "<root>"` (kills cmd/node with `server\index.js`, then re-launches via WMI + `start-server.ps1`). Static assets are served from disk with `?v=<mtime>` and fresh headless profiles each run — no cache invalidation needed for JS/CSS edits, and NO server restart for client-only changes.

## Config & secrets

- `config.json` holds `secret`, `broadcast_secret`, `DEV_MODE`, `socket_port`, `base_url`, TURN creds. Read once via `app_config()/appConfig()` (cached).
- `DEV_MODE: true` returns the OTP in API responses and logs it to `dev_otp.log`. **Currently `true` locally** (no SMS gateway). Must be `false` in production. config.json is a tracked secret; never push its current value.
- Passwords are bcrypt via `bcryptjs` (`server/lib/pwd.js`). Legacy **plaintext** rows are still accepted and transparently upgraded (`verifyAndUpgradePassword`). Don't remove that path.
- Admin seed (auto-created on empty DB): credentials come from `config.json` `admin` section (local, gitignored) or env `BM_ADMIN_USER/BM_ADMIN_PASS/BM_ADMIN_EMAIL/BM_ADMIN_PHONE` — NO credentials in source/README; without them seeding is skipped (`Admin seed skipped` in log). Login flows: `POST /login/phone` → `POST /login/verify {phone, code, purpose}` (DEV_MODE returns the code), or `POST /login/email {email, password, csrf}`.
- DB: SQLite at repo root as `black_meet.db` (`node:sqlite` `DatabaseSync`, WAL). Schema at `server/lib/schema.sql` (idempotent; `db.js` runs it on boot). `BM_DB_PATH` env overrides the file location (used by Render).

## DB / migrations

- The Node app owns `server/lib/schema.sql` — no runtime DDL, no migrations folder, no import tool (`sql/`, `tools/import_sqlite.js`, and `tools/mysql_dump/` were removed). schema.sql also carries the newer tables: `bm_settings` (key/value, holds `signup_mode`), `signup_requests`, `signup_request_messages`; `db.js` runs an idempotent `ALTER TABLE users ADD COLUMN rank` on boot for old DBs.
