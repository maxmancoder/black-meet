# AGENTS.md

Persian (RTL) group voice/video-chat app like Google Meet. Single **Node.js** process: Express + Socket.IO + SQLite (`node:sqlite`), ported from an old PHP/Apache/MySQL app. Local dev on Windows. No tests, no linter, no build step except regenerating Tailwind CSS and the icon sprite.

## Local stack (all started by `start.bat` — double-click)

- Node app `server/index.js` :3000 — web pages (EJS), REST API, Socket.IO, static assets, SQLite. **Apache/MySQL/PHP are gone**; app is only reachable at port 3000, all routes under `/black-meet/*`. All app logs append to `logs/` (`logs\node.log`, `logs\turn.log`, `logs\turn-proxy.log`, `logs\dev_otp.log` — the folder is gitignored and `start.bat` mkdirs it).
- TURN `node turn.js` UDP :3478 (log `turn.log`), TCP relay `node turn-proxy.js` TCP :3478 (log `turn-proxy.log` — must be a SEPARATE file, both used to fight over `turn.log` and the proxy failed to bind).
- Website tunnel = `bin/tunnel.ps1` with fallback **Cloudflare (bin\cloudflared.exe) -> SSH localhost.run -> SSH serveo.net**. Writes the CURRENT public URL to `tunnel_url.txt` only AFTER a health check (`GET /black-meet/login` through the tunnel); copies it to the clipboard and opens it in Chrome once. Exactly ONE chain runs (global mutex + sibling-kill at startup — duplicate instances fight over `tunnel_url.txt`). **All methods point at `127.0.0.1:3000`** (never `localhost` — cloudflared resolves it to IPv6 `[::1]`). Log: `%TEMP%\bm-tunnel\bmt-chain.log`. On this network only Cloudflare resolves (localhost.run/serveo often fail) — the chain retries CF immediately on SSH failure; do NOT pass `--protocol http2` (causes `TLS handshake with edge error: EOF`).
- No bore/TURN tunnel anymore: `turn_host.txt` is read by `server/lib/helpers.js` `turnConfig()` as a legacy override but nothing writes it; cross-NAT media falls back to the metered.ca TURN in `turnConfig()`.
- `start.bat` must stay open and end with `pause` — don't remove the pause. It kills all BM processes when a key is pressed. Echo lines live inside `if` blocks: parentheses in the text break `cmd` block parsing (both branches run) — avoid them.
- `start.bat` falls back to `http://localhost:3000/black-meet/` when no tunnel URL is ready.

## Wiring / gotchas

- `base_url()`/`baseUrl(req)` (server/lib/helpers.js) **hardcodes the `/black-meet` path**. Routes: `/black-meet/login`, `/home`, `/create`, `/profile`, `/meeting?room=…`, `/messages`, `/members`, `/forgot-password`; API at `/black-meet/api/…` (e.g. `api/meetings/create`, `api/messages/conversations`, `api/themes`). The old `.php` alias/redirect layer was REMOVED — `.php` URLs now 404. The root `/socket.io/` path is served at the server root (not under `/black-meet`).
- The call-page member info panel fetches `GET api/members/:userId` (usable only for two users sharing an active meeting, or self).
- Always build URLs with `asset_url()/assetUrl()`/`asset()` — it appends `?v=<mtime>`. Hardcoded css/js paths are the classic "my change isn't showing" bug.
- Socket.IO event names are defined once in `shared/socket-events.js` (browser global `BMEv`, and `require`d by Node). Add/change events there, not as inline strings.
- Socket auth is an HMAC token (`makeSocketToken`/`verifySocketToken`), 24h TTL, `cfg.secret`. Watch the `|` delimiter format `userId|meetingId|ts.sig`.
- `server/lib/internal.js` is called directly by sockets (no HTTP hop). `broadcast_secret`/`BM_BROADCAST_SECRET` is unused but still read by `config.js`.
- Sessions are SQLite-backed (`bm_sessions`), cookie `bm`, httpOnly + SameSite=Lax + Secure-over-https. CSRF = 32-hex token in the session, verified on every POST (`csrfToken`/`csrfValid`). `establishLoginSession` rotates the sid on login.
- UI is Persian RTL; templates are EJS under `server/views/` (`head.ejs` partial). Keep UTF-8.
- `head.ejs` injects `window.BASE`, `window.__BM_LIVE_URL` (empty for logged-out pages — otherwise every page hammers `api/socket-token` with 401), the favicon link, `BM_SPRITE` + `assets/js/icons.js`, and `<link href="/black-meet/theme.css">` AFTER `tailwind.css`. **`assets/css/styles.css` is a BLOCKING stylesheet + two font preloads + sprite preload** — it was `media="print" onload` (async) once, which made `<svg class="bm-ico">` (no width/height) render at the SVG default 300×150 until CSS landed → giant layout jump on every page load. Don't reintroduce async CSS.
- **Ranks / daily quotas** (`server/lib/ranks.js`): `users.rank` ∈ `user|admin|premium` (+ `is_manager` = the seeded main manager account, always highest). Daily meeting-create limits: user=2, admin=5, premium=15, manager=unlimited, enforced server-side in `POST /api/meetings/create` (counted by local date `substr(created_at,1,10)`, resets at midnight, error msg contains `سقف تماس امروز`; response also carries `quota`/`quotaText`/`quotaFull` for the UI). `canViewMembers`/`canViewRequests`/`canDecideRequests`/`canManageUsers` gate `/members` (pages: `requireMembersAccess`) and the APIs; admin rank SEES requests but cannot approve/reject (403 `دسترسی ندارید`), premium sees both members+requests, manager has everything and his rank/row can't be changed by anyone else (`info_hidden` redaction hides his email/phone/username/hash from non-managers; client renders the note instead).
- **Signup modes** (`server/lib/settings.js`, key `signup_mode` in `bm_settings`): `open` (default, full signup + OTP) | `approval` (insert into `signup_requests`, reply `{ok:true, pending:true}` + the fixed PENDING_SIGNUP_MSG, NO account until approved, login blocked, applicant chats the manager via `/forgot-password?id=<phone>` → messages land in `signup_request_messages`) | `closed` (no insert, `SIGNUP_CLOSED_MSG` with 10s toast). ## Tooling / process pitfalls (this environment)

- Shell is PowerShell; `node -e` with regex/quotes is fragile — write scripts to `$env:TEMP\opencode\*.js` and run with `$env:NODE_PATH = "<repo>\node_modules"`.
- **NEVER let a shell command line contain `bin\tunnel.ps1` or `tunnel.ps1`**: its startup cleanup Stop-Kills every powershell whose command line matches that pattern, including the tool's own shell (commits suicide, takes the session with it). Create helper scripts with the file tools (`restart-chain.ps1`, `stop-all.ps1`, `debug-chain.ps1` in `$env:TEMP\opencode\`) and invoke them with `powershell -File`.
- Background processes started with `Start-Process` get killed by the harness; use WMI instead: `([wmiclass]'Win32_Process').Create('cmd /c "cd /d <root> && node server\index.js >> <log> 2>&1"')`. If the root path contains non-ASCII (this repo's Persian path), DON'T put it in a `.cmd` file (cmd reads batch in ANSI → garbled): make an ASCII `.ps1` that takes the root as a param (`start-server.ps1` in `$env:TEMP\opencode`, started via WMI `powershell -File … "<root>"`). To bounce the server after code changes use `restart-server.ps1 -Root "<root>"` (kills cmd/node with `server\index.js`, then re-launches via WMI + `start-server.ps1`). Static assets are served from disk with `?v=<mtime>` and fresh headless profiles each run — no cache invalidation needed for JS/CSS edits, and NO server restart for client-only changes.

## Config & secrets
